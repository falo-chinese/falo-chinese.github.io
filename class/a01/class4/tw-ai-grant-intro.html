Class 04 專屬技術重構案例剖析

AI KM 建置範例：台灣政府 AI 補助工具採集與 RAG 智慧檢索系統

企業級 AI App 設計 pattern 與軟體工程觀念藍圖
📅 上課時間：2026/06/28 (日) 👨‍🏫 授課教師：鄭穎臨 老師

🎯 專案重構定位與教學目的

本專案並非直接套用外部的公務查找工具，而是專為 Class 04 內訓課程精心重構、優化的企業級 RAG 示範專案。 我們將真實世界中「政府多管道補助資訊碎片化」的商業痛點作為載體，重構成一個在架構上具備極高安全性、成本可行性與極致部署效能的 AI 原生應用（AI App）。

透過本專案，學員將跳脫「Chatbot 即 AI 應用」的狹隘認知，深刻理解如何將逆向資料採集、輕量前端 TF-IDF、Token payload 防護、以及 Context Caching（上下文快取）減費技術融入正式的軟體開發管線中，打造符合天心 ERP 下一代 AI 生態圈架構的產品。

5 ARCHITECTURAL PATTERNS

💡 專案蘊含的五大核心軟體工程觀念

點擊或瀏覽以下五個卡片，理解我們如何透過軟體設計架構，解決企業落地 AI 的真實痛點：

CONCEPT 01 / 工程務實主義
輕量化地端 TF-IDF 檢索
捨棄昂貴且架構複雜的伺服器端向量資料庫（Vector DB）。針對 224 筆補助案這種中小規模的企業內部專屬知識集，利用前端字元級 TF-IDF 引擎（如 MiniSearch）即可在毫秒內完成精準檢索，大幅降低維運門檻與基礎設施成本。
CONCEPT 02 / 物理與安全防禦
Token 物理防護與邊界管理
在將數據送往雲端大模型之前，前端預檢機制嚴格限制 Payload 上限為 4,096 tokens。此物理邊界防禦不僅徹底杜絕超長文本导致的 API 刷爆財務風險，還有效攔截了惡意提示詞注入（Prompt Injection），建立健全的企業 AI 安全意識。
CONCEPT 03 / 企業落地經濟學
Context Caching 雲端快取技術
每次 RAG 對話如果都要將整份數據庫傳送給 LLM，Token 費用將成線性暴漲。本專案示範如何調用 Gemini API 的 Context Caching 技術，將 224 筆工具庫快取在雲端，使後續的對話診斷成本降低 90%，解決企業 AI 應用的經濟可行性問題。
CONCEPT 04 / 結構化價值交付
從「對話」到「商務白皮書」
企業 AI 應用的終點絕非只是個聊天機器人。本專案展示了如何將 AI 的多維度診斷結論，在前端直接渲染成一份排版精緻、無廣告干擾的 Notion 風格 HTML 轉型建議書，一鍵即可列印或存為 PDF，實現「對話即交付」的高商務價值。
CONCEPT 05 / 零運維極致部署
100% 自包含單頁應用 (SPA)
將 224 筆政府補助案黃金資料庫與檢索引擎、UI 邏輯完全封裝於單一 HTML 檔案中。無任何 CORS 跨域限制，可完全離線運行或透過本地 file:// 直接開啟，展示了如何設計「零伺服器成本、零維運死角」的極致高可用 AI App。
